Skill routing

프롬프트가 들어올 때마다 이 기기에 설치된 스킬 · 에이전트 · 위키 중 관련 있는 것을 찾아 컨텍스트에 붙여 줍니다. 후보는 키워드 검색(BM25)으로 뽑고, 의사결정 모델(Jev)이 순서를 다시 매깁니다.

How it works

  1. 01설치된 스킬 · 에이전트 · 커맨드 설명과 위키 색인을 키워드 검색(BM25)

  3. 03의사결정 모델(Jev)이 스킬 후보 · 최근 사용한 스킬 · 위키 전체 목록을 판정해 순서를 다시 매기고, 1 · 2위가 애매하면 붙이지 않음, 실패하면 BM25 결과를 그대로 사용
  4. 04같은 의사결정 호출에서 프롬프트 난이도도 판단해 턴마다 effort 를 고름 — 세션 설정보다 높이지는 않음
  5. 05알려 주기만 하고 무엇을 쓸지는 에이전트가 판단

Jarvis · Injection

Injection

프롬프트가 입력될 때마다 설치된 스킬 · 에이전트 · 커맨드와 위키에서 관련 항목을 찾아 Claude 컨텍스트에 추가합니다. 호출은 강제하지 않습니다.

  1. 01Prompt사용자가 보낸 메시지
  2. 02FilterCut맞장구 · 슬래시 커맨드 · 다른 에이전트가 쓴 글처럼 라우팅할 필요 없는 입력 제외
  3. 03BM25키워드 매칭으로 스킬 · 에이전트 · 커맨드 · 위키 후보 추출
  4. 04Decision의사결정 레이어 · 의사결정 모델(Jev)로 후보를 뜻 기준으로 재정렬
  5. 05Inject고른 항목만 Claude 컨텍스트에 몇 줄로 주입
  • Jev 가 고른 항목
  • BM25 순위 그대로
  • Jev 실패 · 입력 제외

예시로 만든 턴을 차례로 재생합니다. 실제 프롬프트나 위키 페이지가 아닙니다.

Jarvis · Office mode

Office mode

기획부터 머지까지 SDLC 각 단계를 역할 워커가 나눠 맡고, 메인 세션이 작업을 배분하고 결과를 판정하는 개발 방식입니다.

워커 간 핸드오프는 모두 메인을 거칩니다. 검토 · 검수 결과에 따른 되돌림도 메인이 처리하며, 단계마다 최대 2회입니다.

테스트 · 린트를 통과하면 명세 · 시안 · 코드 검수를 동시에 실행합니다. 메인은 세 판정을 취합해 다음 처리를 정하고, 2차 검수는 수정된 diff 만 검토합니다.

규칙을 어기는 동작은 훅이 즉시 차단합니다. 차단마다 상한이 있으며, 상한을 넘으면 기록을 남기고 통과시킵니다.

단위마다 워커가 별도 워크트리에서 작업하고, 메인이 의존 순서와 승인 순서에 따라 작업 브랜치에 머지합니다. 같은 파일을 수정하는 단위는 한 워커에 배정하거나 순서를 정합니다.

이 포트폴리오의 Jarvis 서브페이지 작업 한 건의 커밋 기록입니다. 기획 · 디자인이 끝나면 탭 단위는 별도 워크트리에서 동시에 진행되어 연달아 머지됩니다.

개입 단계가 높을수록 작업 중 승인 지점이 줄어듭니다. 기본은 3입니다.

작업 중에는 작업용 문서에 진행 상황과 결정을 기록합니다. 작업이 끝나면 남길 결정을 보존 문서에 반영하고, 작업용 문서는 삭제합니다.

Jarvis · Architecture

Architecture

자체 플러그인과 외부 플러그인을 한 마켓플레이스에서 관리합니다.

화살표는 플러그인 간 의존 관계를 나타냅니다.

hance-designer 는 화면 작업, hance-writer 는 문서 작업을 담당하며 세부 판단은 외부 플러그인에 위임합니다.

에이전트에는 공통 규약 스킬 하나만 preload 하며, 나머지 스킬은 필요할 때 호출해 토큰 사용량을 줄입니다.

플러그인 실행 로그는 로그 폴더에, 위키 페이지는 별도 위키 레포에 저장됩니다. 로그는 터미널 옆 패널과 로컬 브라우저 허브에서 확인합니다.

Jarvis · Layers

Layers

프롬프트가 입력되면 훅 하나가 비용이 낮은 단계부터 순서대로 실행합니다.

라우팅은 후보 탐색 단계와 후보 선택 단계로 구성됩니다. 단계를 선택하면 해당 단계의 입력과 출력이 표시됩니다.

같은 이벤트에 등록된 훅은 병렬로 실행되며 서로 통신하지 않습니다. 비동기 훅은 완료를 기다리지 않습니다.

위키 검색은 단계(L0~L4)마다 역할이 나뉩니다. 훅은 후보를 제시하고, 범위를 좁히는 판단은 스킬이 수행합니다.

라우팅 단계는 다음 원칙에 따라 나뉩니다.

Jarvis · Roles

Roles

메인 세션이 작업을 분배하고, 역할 워커가 맡은 단계를 처리합니다.

워커 간 직접 연결은 없으며 모든 요청은 메인을 거칩니다. 훅은 즉시 차단만 하고, 대기는 워커가 처리합니다.

역할 키는 워커가 따를 역할 스킬을 연결하는 인터페이스입니다. 새 역할은 역할 스킬을 추가해 정의하며, 아래는 현재 정의된 역할입니다.

워커는 일반 세션으로 실행하고, 역할은 훅이 세션 시작과 compact 직후에 주입합니다. 에이전트 파일 방식은 기본 시스템 프롬프트가 바뀌고 훅 설정이 무시되어 사용하지 않습니다.

서브에이전트는 화면 작업과 문서 작업으로 나뉘며, 각자 공통 규약 스킬 하나만 preload 합니다.

Jarvis · Decision engine

Decision engine

Decision engine 은 라우팅 · 작업 강도 추천 · 학습 · 오피스 모드의 판단 장치를 묶어 부르는 이름입니다.

판단 장치가 라우팅 · 작업 강도 추천 · 학습 · 오피스 모드 흐름의 어느 지점에서 동작하는지 표시합니다.

의사결정 레이어는 의사결정 모델(Jev)로 후보의 순서를 조정하거나 추천을 보류합니다. 스킬은 키워드 검색(BM25) 후보와 최근 사용한 스킬을, 위키는 전체 목록을 판정하며, 호출이 실패하면 BM25 결과를 사용합니다.

의사결정 모델(Jev) 호출이 실패하면 해당 턴은 키워드 검색(BM25) 결과로 주입합니다. 실패가 연속되면 일정 시간 호출을 중단한 뒤 다시 시도합니다.

주입한 스킬을 실제로 썼는지 · 쓰지 않았는지 · 놓쳤는지를 언어별로 측정해 학습 사전을 갱신합니다. 새 사전은 승격 게이트 조건을 모두 통과해야 적용됩니다.

오피스 모드의 결정 권한은 L0~L3 단계로 나뉘며, L0에 가까울수록 권한이 큽니다. 의사결정 레이어(L2)는 조언만 하고 변경 권한은 없습니다.
