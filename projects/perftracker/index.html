"성능을 재는 데 드는 시간" 부터 줄이기

PROBLEM
  • Macrobenchmark — 소스 필요, 화면마다 벤치마크 클래스 · UiAutomator 시나리오 새로 작성
  • Perfetto UI — 트레이스 import · export · 쿼리 지식 필요
  • 기타 오픈소스 — 커스텀 불가 · 유료화 · 성능 저하
  • 측정이 번거로워 계속 뒤로 밀림
DECISION
  • 문제 재정의 — "성능이 나쁜가" 보다 "성능을 재는 데 드는 시간" 부터
  • OS 가 이미 남기는 신호 활용 — Perfetto 트레이스 + 측정 전후 dumpsys 스냅샷
  • adb 연결만 되면 start / stop 두 명령으로 측정
  • 측정 중에는 기기에 adb 명령 0회
WHY
  • Apptim 등 기존 도구와 비교해 없는 부분만 직접 구현
  • 측정 중 보내는 명령 하나도 CPU · 로그 수치를 흔듦 → 측정이 성능을 오염
  • 그래서 스냅샷은 시작 직전 · 종료 직후 두 번 — 누적 카운터라 차이가 곧 세션 값
  • 트레이스는 기기에서 자체 기록 → stop 시 일괄 회수, 계산은 전부 PC 에서
RESULT
  • 벤치마크 클래스 작성 ~ 트레이스 직접 분석 → start / stop 두 명령 + 보고서 한 장
  • 기기는 측정 단계에만 필요 — CI 에서 측정 러너와 계산 · 검증 분리
  • Maestro 로 반복 측정 — 새 화면은 코틀린 벤치마크 클래스 대신 yaml 한 장

판정하지 않는 결과

  • 도구가 “느리다 / 좋다” 를 정하지 않음 — 기준은 사용처(CI · 리포트 · 사람)가 결정
  • 한 세션 안에도 프레임 마감 8.33ms · 16.67ms 공존 → 16.67ms 고정 시 120Hz 기기에서 오판
  • 측정 못 한 값은 0 대신 null + 사유 코드 — 실제로 잰 0 과 구분

한계

  • Perfetto UI · Studio Profiler 대체 아님 — 스레드 분석 · 콜스택 · 힙 프로파일 제외(켜는 순간 측정이 성능을 오염)
  • 대신 세션마다 원본 트레이스 보관 → ui.perfetto.dev 에서 상세 분석
  • GPU · 배터리 제외 — 칩 벤더마다 경로가 다르고, 배터리 관련 정보는 산출 불가
