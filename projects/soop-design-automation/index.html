Tooling · Design system

–디자인 리소스 자동화

Figma 토큰 · 아이콘을 SSOT 레포 하나로 관리해 각 플랫폼에 반영하는 디자인 리소스 파이프라인

PERIOD
2025.12 — 2026.03

Figma 플러그인

PROBLEM
  • 디자이너가 컬러 · 아이콘 변경을 따로 공지하고 개발자가 코드에 직접 반영 → 실수 · 누락 위험
DECISION
  • Figma 플러그인에서 컬러 · 아이콘 추출 후 Android 프로젝트에 MR 자동 생성
  • 컬러 전체 덮어쓰기, 여러 아이콘 일괄 반영
RESULT
  • 디자이너 작업 → 플러그인 실행 → MR 자동 생성으로 반영 과정 단축

전사 파이프라인 설계

PROBLEM
  • 변환 로직이 플랫폼별 플러그인 안에 있어 각 팀이 직접 수정 불가
  • 플랫폼마다 따로 반영 → 플랫폼 간 버전 불일치 · 변경 이력 부재
DECISION
  • 플러그인은 원본(JSON · SVG) 추출 · 푸시 전용, 변환 로직 제거
  • 매니페스트 파일에 키별 해시 저장, 해시 비교로 변경된 토큰 · 아이콘 식별
  • 토큰 레포를 SSOT 로 두고 푸시 시 웹훅으로 각 플랫폼 CI 호출
  • 각 CI 가 변경분을 감지해 플랫폼 형식으로 변환, MR 생성 · Teams 알림
  • 배포는 디자이너, 플러그인 · 레포 구축은 개발자, 변환 스크립트는 각 플랫폼 팀으로 역할 분리
  • Foundation 토큰(컬러 · 타이포 · 스페이싱 · 아이콘)부터 시작하고 컴포넌트 변경 감지는 다음 단계로 분리
WHY
  • 플랫폼마다 변환 방식이 달라 팀별 독립 수정 필요(Android 는 VectorDrawable 변환, iOS · Web 은 SVG 그대로)
  • 전체 내보내기 대신 변경분 처리로 응답 속도 개선
  • Git 이력으로 변경 추적
  • 플러그인 유지보수 부담 제거

방향 합의

  • 토큰을 한곳에서 관리 · 추출하고 구현은 각 플랫폼에 맡기는 방향 합의
  • 전사 회의에서 토큰 레포에 원본 유지, 플랫폼별 CI 변환 구조로 결정

Figma 컨설팅

  • 기획한 SSOT 관리 · 플랫폼별 파이프라인 구조를 모범 사례로 확인

컴포넌트 설계

  • 슬롯으로 구성된 컴포넌트는 변경 감지가 되지 않아 자동 업데이트 불가 → 아톰은 고정 프로퍼티로, 슬롯은 시트 · 다이얼로그에 한정
  • 컴포넌트 변경 감지에 디자이너 지정 노드와 자동 감지 병행

토큰 스펙

  • Figma 컬러 변수 · 텍스트 스타일을 토큰 레포에 JSON 으로 커밋하는 스키마 정의
  • 커밋 정보 · 컬렉션 구조 · 값 · 별칭 · 모드 포함
