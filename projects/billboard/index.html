YouTube 플레이어 하나로 메인 · 리스트 팝업 재생

차트를 스크롤하거나 리스트 팝업으로 바뀔 때 영상이 끊기지 않게 하는 데 중점을 뒀습니다.

  • View 기반 YouTube 플레이어를 AndroidView 로 Compose 에 붙이고, Circuit Presenter 가 rememberRetained 로 플레이어 View 단일 인스턴스 유지
  • 메인 · 리스트 팝업 전환 시 같은 View 를 기존 parent 에서 removeView 후 재부착해 재생 유지
  • 플레이어는 LazyColumn 밖 외부 스크롤에 두고 nestedScroll 로 연결, 차트 탭이 sticky 되는 시점에 리스트 팝업으로 전환
  • 리스트 팝업은 VelocityTracker 기반 드래그, 손 뗀 위치 기준 좌우 앵커 스냅, 화면 밖 방향 fling 시 dismiss
  • YouTube Data API 의 국가별 차단 목록(regionRestriction) · 국내 영상물 등급(kmrbRating) 으로 국내 재생 불가 영상을 미리 걸러 썸네일과 안내 표시

에이전트 리뷰 · 릴리즈 자동화

혼자 개발하다 보니 코드를 봐 줄 사람이 없어서 릴리즈 PR 마다 리뷰 에이전트가 먼저 보고 배포까지 이어지는 흐름을 만들었습니다.

  • GitHub Actions 에서 Claude 리뷰 에이전트 3종(앱 규칙 · Compose · 모듈 경계)을 병렬 실행
  • .claude/rules 를 단일 출처로 두고 세 리뷰어가 같은 규칙 참조
  • 같은 PR 에서 CI 에뮬레이터로 Baseline Profile 생성 · 커밋
  • Major · Minor 지적이 0 이면 auto-merge, 머지 시 태그 · 서명 APK · GitHub Release 자동 생성
  • 릴리즈 PR 7개에서 지적 47건, 모듈 의존 위반 · 매 프레임 recomposition 등을 리뷰에서 발견

홀로그램 카드

곡을 길게 눌러 모으는 회전 카드입니다. 렌더링 방식과 셰이더 질감을 여러 번 바꿔 가며 만들었습니다.

  • 앞면 메탈릭 홀로그램 · 뒷면 브러시드 스틸
  • drawWithCache 오버레이(SrcAtop) → 별도 Canvas 레이어 → RenderEffect 후처리 순으로 렌더링 방식을 바꾸고, 질감도 레인보우 · Blinn-Phong · 레코드판 · 메탈릭 순으로 시도
  • API 33+ 는 RenderEffect + AGSL RuntimeShader 로 앨범 아트를 inputShader 로 받아 후처리, API 32 는 Compose Canvas(SweepGradient) 로 근사
  • 손으로 돌리다 놓아도 관성 회전에서 자동 회전으로 자연스럽게 이어지도록 회전 각도를 Animatable 하나로 관리
  • 각도는 graphicsLayer · drawWithContent 람다에서만 읽어 draw phase 로 격리, 회전 중 recomposition 제거

에이전트 기반 SDLC 도입

카드 그룹 기능을 기능 명세부터 릴리즈까지 에이전트와 한 사이클로 개발했습니다.

  • 기능 명세(Spec) 작성 후 결정 사항을 확정해 승인
  • 구현 계획을 Task 29개로 나누고 subagent 가 Task 단위로 구현 · 커밋
  • 구현 후 디자인 핸드오프 기준으로 UI 재구성(재생은 홈 전용 · 사이드바 그룹 생성 · 5색 팔레트)
  • PR 전 리뷰에서 design-system 모듈이 data 모델을 api 로 노출하던 의존을 찾아 domain Group 모델 · UI 전용 GroupBadge 로 분리
  • 릴리즈 PR 리뷰 지적은 같은 PR 에서 반영 후 릴리즈, 9장 제한 제거 · 그룹 생성 · 삭제 · 카드 그룹 이동 출시
  • 사람 몫은 명세 승인 · 수동 스모크 테스트 · 머지

서버 없는 차트 수집

서버를 따로 두지 않고 GitHub Actions 와 Pages 만으로 차트 데이터를 받아 오게 했습니다.

  • 파이썬 스크래퍼 4개(Hot 100 · Billboard 200 · Global 200 · Artist 100) → JSON → GitHub Actions 커밋 → GitHub Pages
  • 앱은 Pages 주소를 그대로 API 로 사용
  • 순위 변동(New · Rising · Falling · Steady · Re-Entry)은 수집 단계에서 계산
  • 빌보드 갱신 지연(공휴일 등)에 대비해 매일 체크, 데이터가 바뀐 경우에만 커밋
  • 초기 세팅 이후 별도 운영 없이 자동 갱신 중
