2026.05

블러 최적화

PROBLEM
  • 원본 크기 그대로 만든 블러용 비트맵의 메모리 소모
  • OS 12 미만 CPU 블러(RenderScript)는 radius 상한이 낮아 블러 · 크롭을 세 번 반복
  • 화면마다 제각각 구현된 정적 블러
DECISION
  • 디코딩 시점에 가로 · 세로 1/4(픽셀 수 1/16)로 다운샘플
  • OS 12 미만 Glide → Coil 전환, 변환 체이닝으로 반복 블러 · 크롭 제거
  • 정적 블러를 단일 모듈(컴포넌트 2종)로 통합
WHY
  • 블러 비용이 비트맵 크기 × radius에 비례해 알고리즘보다 입력 크기 축소가 우선
  • 화면별 구현 대신 컴포넌트로 재사용
RESULT
  • 블러가 많은 화면을 같은 동선으로 끝까지 스크롤 시 앱 총 메모리 증가 +268MB → +8MB, Graphics +145MB → −26MB
  • 배포 후 Play Vitals LMK 하향 추세
  • 팀 공용 블러 모듈로 사용, "다운샘플링 가능하면 필수" 가이드 공유
  • 정적 블러를 리팩토링 작업에서 분리해 선배포
  • 축소 레이어에서 블러 후 확대하는 Compose Modifier 검증

2026.01 — 2026.02

홈 신규 캐러셀 섹션

앱 샘플을 먼저 만들어 회의에 공유하며 디자인까지 함께 작업한 신규 섹션

  • 디자인 확정 전 Horizontal Pager · Card Stack 두 안을 앱 샘플로 구현해 실제 동작 비교
  • 썸네일 모서리 띠 배지 제안과 프로토타입 → 1차 스펙으로 채택, 이후 신입 스트리머 노출 등 다른 홍보 영역에도 재사용
  • 태블릿 실기기에서 화질 · 광고 배치 문제 먼저 제기 → Phone 은 Card Stack, Tablet 은 Horizontal Pager 로 분기
  • Card Stack 은 LazyLayout 으로 카드 3장만 배치 · 무한 순환, 가로 드래그를 consume 해 카드 탭 · 세로 스크롤과 분리
  • 재생 조건을 포커스 · 가림 여부(광고 확장 · 다이얼로그) 두 상태로 분리, 두 레이아웃이 Preview State Holder 공유
  • 스와이프 · 클릭 로그로 기존 캐러셀 대비 인터랙션 증가 확인
