기기 안에서 만드는 퀴즈

읽은 노트로 바로 복습할 수 있게, 기기 안 모델로 4지선다 퀴즈를 만드는 데 중점을 뒀습니다.

  • Gemma 4 E2B 를 LiteRT-LM GPU 백엔드로 실행, 엔진은 첫 요청 때 만들어 앱 전체가 하나를 재사용하고 Mutex 로 요청 직렬화
  • thinking 끄기 · greedy 디코딩 · 문항당 340 토큰, 입력 노트는 2,000자로 잘라 대기 시간 단축
  • 깨진 출력은 파서가 문항 단위로 복구하고 실패를 Parse · Empty · Engine 으로 구분, 문항 수를 줄여 재시도
  • 시간 초과 · 취소 시 cancelProcess() 로 네이티브 디코딩까지 중단해 다음 퀴즈가 막히지 않게 처리
  • 퀴즈를 쓰기 전에는 엔진을 올리지 않아 평소 메모리는 그대로

퀴즈 모델 런타임 다운로드

모델 용량(2.6GB)이 커서 앱에 포함하지 않고, 퀴즈를 쓰려는 사용자만 앱 안에서 선택해 내려받도록 구현했습니다.

  • WorkManager 포그라운드 작업(dataSync)으로 받기, Wi-Fi 등 비종량제 네트워크 · 저장 공간 여유가 있을 때만 시작
  • .part 임시 파일에 Range 요청으로 이어받기, 앱을 강제 종료해도 받던 지점부터 재개 — 서버가 Range 를 무시하면 처음부터 다시
  • 크기 · SHA-256 검증을 통과해야 모델 위치로 원자적 이동 — 받다 만 파일을 엔진이 열어 생기는 네이티브 크래시 차단
  • 여유 공간이 부족하면 받기 전에 차단, 모델을 지우면 엔진 메모리도 함께 해제
  • 진행 · 실패 · 완료 알림은 상태당 하나만 유지

공부 기록 · AI 주간 요약

읽기와 퀴즈 기록을 기기 안에 쌓아 기간별로 보여 주고, 같은 온디바이스 모델로 주간 요약과 틀린 문제 패턴을 만듭니다.

  • 주 · 월 · 전체 기간별 읽기 · 퀴즈 · 북마크 통계, 지난 요약 모아 보기
  • 하루 한 번 충전 중에 주간 요약 · 틀린 문제 패턴 생성(WorkManager)
  • 요약 문장에는 숫자를 쓰지 않게 하는 숫자 · 근거 · 베끼기 가드 — 수치는 화면이 직접 표시
  • 실기기 평가 — 주간 요약 9/10 · 틀린 문제 패턴 6/6
  • 북마크 화면은 가장 최근 항목을 큰 카드로 강조, 해제한 직후에는 되돌리기 제공

마크다운 노트 동기화 · 리더

노트 원본은 앱 밖 GitHub 레포에 두고, 바뀐 노트만 받아 블로그 글처럼 읽게 했습니다.

  • index.json 의 해시로 바뀐 노트만 골라 받고, 본문은 동시에 받기
  • 반영은 Room 트랜잭션 한 번 — 받다 실패하면 하나도 반영하지 않아 목록이 어중간하게 남지 않음
  • JetBrains GFM 파서로 마크다운을 블록(제목 · 코드 · 표 · 인용 · 체크 목록 …)으로 변환, 파서는 별도 모듈로 분리
  • 형식이 틀린 노트는 그 노트만 원문 보기로 남김 — 노트 하나 때문에 동기화 전체가 멈추지 않음
  • 저장소 연결 화면 — 링크 붙여넣기 → 확인 → 첫 동기화

Adaptive UI

Android 공식 윈도우 크기 클래스를 브레이크포인트로 삼아, 윈도우 크기에 맞춰 레이아웃이 바뀌도록 구현했습니다.

  • 브레이크포인트 — Compact < 600dp · Medium 600dp · Expanded 840dp · Large 1200dp · Extra-large 1600dp
  • Compact 는 노트 목록을 드로어로, Medium 이상은 목록 패널을 고정한 목록 · 상세 2단 배치(ListDetailSceneStrategy)
  • Expanded 이상은 하단 바 대신 레일 내비게이션
  • 여백 · 카드 간격 · 본문 최대 너비를 브레이크포인트별 토큰으로 관리 — 화면 코드는 분기 없이 토큰만 사용

에이전트 기반 SDLC

기획 · 디자인 · 구현 · 검수 · 검증을 역할별 에이전트가 나눠 맡는 SDLC 로 개발하고 있습니다.

  • 새 기능은 기능 명세(PRD)부터 작성, 기존 기능도 코드와 실기기 동작을 기준으로 명세 정리
  • 구현과 검수 모두 같은 명세를 기준으로 진행, 구현 쪽이 더 타당하면 명세에 반영
  • 모듈별 AGENTS.md 로 작업 규칙 제공, 빌드로 확인할 수 있는 규칙은 빌드 단계에서 강제
  • E2E 검증 — 폴더블 에뮬레이터(접힘 · 펼침 · 가로)와 실기기를 adb 로 조작, 실기기에서만 재현되는 버그 5건 수정
  • 변이 테스트 — 코드를 의도적으로 틀리게 바꿔 테스트가 실패하는지 확인

앱 기반 구조

화면마다 상태 관리와 화면 이동을 같은 방식으로 다루도록 공통 기반을 만들었습니다.

  • MVI 베이스 — 구독한 값이 바뀌면 build() 로 상태 전체를 다시 만들고, 일회성 이벤트는 고유 id 로 전달
  • 화면 이동 — 백스택은 Navigator 한 곳에서 관리하고, 연속 탭은 dispatch 단계에서 쓰로틀
  • 의존은 바깥에서 안쪽으로 — 인터페이스는 안쪽 모듈이 정의하고 바깥 모듈이 구현
  • 테마 — MaterialTheme 대신 CompositionLocal 로 다크 테마 구성
  • 빌드 — 컨벤션 플러그인 · 버전 카탈로그로 모듈 설정 통일, R8 축소 적용
