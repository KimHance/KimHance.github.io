2025.07 — 2025.08

백그라운드 복귀 갱신 정책

PROBLEM
  • 백그라운드에 10분 이상 머물면 앱을 강제로 다시 실행하는 기획 초안
DECISION
  • 백그라운드 60분 이상이면 앱 재실행 대신 화면 갱신
  • 복귀 감지 Effect 를 공통 Pull to Refresh 레이아웃에 구현해 이를 사용하는 모든 화면에 화면별 코드 없이 적용
  • 복귀 갱신도 당겨서 새로고침과 같은 onRefresh 를 호출하고 목록은 맨 위로 스크롤, 갱신 시각은 CompositionLocal 로 하위 화면에 전달
  • PIP 플레이어 상태는 갱신 대상에서 제외
WHY
  • 국내 앱도 재시작하지 않고 화면 갱신, 분 단위로는 콘텐츠 변화가 거의 없음
  • 모든 목록 화면이 같은 Pull to Refresh 레이아웃을 사용해 한 곳 수정으로 앱 전체 적용
RESULT
  • 근거를 제시해 기획 정책 변경
  • 복귀 갱신 정책을 앱 전체 목록 화면에 한 번에 적용

2025.07 — 2025.08

웹뷰 이벤트 페이지

PROBLEM
  • 이벤트 키를 앱에 넣어 두면 이벤트가 바뀔 때마다 앱 업데이트(심사 · 배포) 필요
DECISION
  • 운영 중 이벤트를 API 로 조회하도록 서버와 협의, 이벤트 키 · 웹뷰 여부 · URL · 종료일로 이벤트 페이지 노출
  • 웹 이벤트 페이지와 앱을 Bridge 로 연결해 닫기 · 채널 이동 · 외부 URL · 오늘 하루 보지 않기를 앱에서 처리
  • 웹이 넘긴 로그 데이터를 앱이 그대로 사용자 행동 로그로 전송
WHY
  • 이벤트 교체 · 종료를 서버와 웹에서 결정해 앱 배포 없이 운영
RESULT
  • 이벤트마다 앱 업데이트 없이 운영

2025.05 — 2025.08

Baseline Profile

홈 스크롤 P99 프레임 지연
32.1 → 23.1ms (−28%)
카테고리 상세 스크롤 P99 프레임 지연
56.5 → 38.9ms (−31%)
PROBLEM
  • 설치 · 업데이트 직후엔 미리 컴파일된 코드가 없어 사용 기록이 쌓이고 기기 유휴 시간에 컴파일된 뒤에야 빨라짐
  • 그 전까지는 첫 실행 · 첫 스크롤에서 비교적 버벅이는 현상 발생
  • 글로벌 앱은 저사양 기기 비율이 높아 첫 스크롤에서 버벅일 가능성이 더 큼
DECISION
  • Macrobenchmark 로 홈 · 카테고리 상세 스크롤 경로의 Baseline Profile 생성
  • None · Baseline Profile · Warmup + Baseline Profile 세 모드로 비교 측정
  • 앱 시작(홈 진입까지)도 측정해 비교한 뒤 프로파일에서 제외
WHY
  • 설치 시점에 핵심 경로를 미리 AOT 컴파일해 사용 기록이 쌓이기 전 첫 실행부터 Warmup 에 가까운 성능 확보
RESULT
  • 스크롤 영역 컴포넌트의 렌더링 시간을 trace 로 측정, LiveCard 약 39% 단축(Warmup 포함 시 약 58%)
  • Pager 가 있는 카테고리 상세에서 개선 폭이 가장 큼
  • 직접 도입해 팀 주간회의에서 적용 방법 공유
  • 공통 액션 · 사용자 경로(CUJ) 정의, 프로세스를 종료해 첫 실행 상태로 스크롤 측정
  • 화면에 테스트 태그 16곳 · 트레이스 4곳 추가
  • APK 분석으로 프로파일 포함 여부, dexopt 상태로 컴파일 여부 확인
  • Baseline Profile(설치 시 ART AOT 컴파일)과 Startup Profile(빌드 시 DEX 레이아웃 최적화)의 역할 구분

2025.04 — 2025.05

공통 시트 컴포넌트

시트 종류와 종류별 UX 설계, 공통 시트 컴포넌트로 구현

PROBLEM
  • 겉보기엔 같은 시트여도 화면마다 Dim · 바깥 터치 · 높이 정책이 달라 모양만 보고 고르면 디자인 정책과 어긋남
  • 라이브 · VOD 시청 중 띄우는 구독 · 선물 · 투표 시트는 Dim 없이 시트 밖 플레이어도 계속 조작할 수 있어야 함
DECISION
  • 화면 위치 · 용도에 따라 시트를 네 종류로 나눈 시트 정책 문서 작성
  • 일반 화면의 Bottom Sheet · 방송하기 화면의 Bottom Layer · 유저 카드의 Bottom Modal 은 Material3 시트를 래핑해 Dim · 높이 · 닫기 방식을 컴포넌트에 고정
  • 플레이어 위 Bottom Sheet Layer 는 Material3 Anchored Draggable 기반으로 Hidden · Half · Expanded 3단 앵커와 드래그 닫기 구현, 가로 · 대화면에서는 Center Layer Modal 로 전환
WHY
  • 시트 종류를 컴포넌트로 나누면 모양이 아닌 시안의 시트 이름으로 골라 디자인 정책 준수
  • Material3 시트는 Dim 과 바깥 터치 차단이 기본이라 시트를 띄운 채 시트 밖 플레이어를 조작할 수 없음
RESULT
  • 플레이어 위 시트 전반에 적용, 기존 VOD 시트도 이 컴포넌트로 이전
  • 화면 회전 · Center Layer Modal 전환에도 시트 내용 유지, 펼침 상태 저장 · 복원
  • 키보드 노출 시 Expanded 로 펼치고 키보드가 닫히면 이전 앵커로 복원
  • 시트 안 배경 영역의 터치를 소비해 뒤 플레이어로 전달 차단
  • 화면 하단에 고정되는 Sticky Button 을 팀 프로토타입에서 공통 Modifier 로 일반화, 플레이어 위 시트용은 별도 구현
  • 피커가 들어간 시트는 드래그 닫기를 비활성화하고 확인 · 뒤로 가기 · 바깥 터치로 닫기(디자이너 협의)

2025.02 — 2025.07

카테고리 상세 구현

카테고리 상세 화면 구현, 탭별 상태 구조부터 접히는 헤더와 공통 필터 시트까지 설계

목록 요청 분기
4가지
접히는 헤더 구현안 비교
3가지
  • Live · Video · Clip 탭별 Presenter 분리, 공유 상태는 상위 Presenter 가 전달
  • 필터 유지 범위를 기획과 확인해 상태 위치 설계, 언어는 DataStore 로 앱 전체 공유 · 정렬과 기간은 탭 단위 보관
  • 언어 · 정렬 · 기간 필터 시트를 공통 모듈로 구현해 Live · Video · 검색 화면에서 재사용
  • 페이징 요청을 첫 로드 · 필터 변경 · 새로고침 · 더 보기로 분기
  • 접히는 헤더는 3가지 구현안을 비교해 CollapsingToolbar 방식으로 시작, 탭 Pager 와 함께 쓰도록 바깥 세로 스크롤 + NestedScrollConnection 구조로 개선
  • NestedScrollConnection 으로 위로 끌면 헤더가 먼저 접히고 아래로 끌면 목록이 먼저 스크롤
  • 스크롤 offset 은 람다로 넘겨 Layout 단계에서만 읽고 제목 alpha 는 State 로 전달해 스크롤 중 리컴포지션 최소화
  • 정책이 없던 헤더 제목 전환 애니메이션을 먼저 구현해 디자이너와 합의
  • 딥링크 진입 시 카테고리 정보를 조회해 탭과 상단 추천 영역에 전달
  • 관심 없음 · 신고 기능 연결, 관심 없음 처리한 채널은 알림 카드로 전환 · 되돌리기 지원

홈 구현

추천 · 팔로잉 탭 홈 화면 구현

attach · detach 경우
8가지
다시 attach 시점
스와이프가 멈추고 200ms 뒤
  • 추천 · 팔로잉 탭 전환용 공통 TabPager 구현, 동영상 · e스포츠 · 검색 화면에서 재사용, Pager offset 에 맞춰 인디케이터 위치 · 너비와 탭 글자색을 lerp 로 보간
  • 공통 Pull to Refresh 레이아웃을 Material3 PullToRefreshBox 래핑과 Lottie 인디케이터로 구현해 홈 두 탭에 적용
  • 디자인 시스템에 HorizontalPager 기반 Carousel 컴포넌트 구현, 양옆 카드가 보이는 무한 스와이프 · 화면 너비 단계별 카드 비율 · focus 밖 카드 흑백 처리
  • 미리보기 플레이어를 Composable 슬롯으로 주입해 플레이어 개발 일정과 분리, State Holder 하나로 관리, 플레이어는 focus 된 카드에만 attach, 스와이프 · 앱 Lifecycle · 이벤트 페이지 오버레이에 맞춰 detach · pause
